# Google Sign-In — Android SHA-1 fingerprints

Native Google Sign-In on Android (`@react-native-google-signin/google-signin`)
verifies the **signing certificate** of the installed app against fingerprints
registered in Firebase / Google Cloud. If the fingerprint of the build a user is
running is not registered, Google Sign-In fails with `DEVELOPER_ERROR`
(`statusCodes` code **10**) — the rest of the app still works, but the Google
button silently errors.

iOS Google Sign-In and Apple Sign-In need **no SHA-1** (see the bottom of this
doc). This page is Android-only.

> Background: the app code is correct — see
> [`src/features/auth/googleAuth.ts`](../src/features/auth/googleAuth.ts) and
> [`src/features/auth/socialAuthConfig.ts`](../src/features/auth/socialAuthConfig.ts).
> Client IDs live in `app.json` → `expo.extra`. The only thing that ever needs
> changing for new build keys is the registered SHA-1 set + `google-services.json`.

---

## Why "test" and "production" SHA-1 differ

We build with **EAS** and ship an **app bundle** to Google Play (`eas.json` →
`production.android.buildType: "app-bundle"`, submitted to the internal track).
That means **Google Play App Signing** is in effect, and there are up to **three
different signing keys** in play — each with its own SHA-1:

| Key | Used for | Where the SHA-1 comes from |
| --- | --- | --- |
| **Debug / development key** | Local debug + EAS `development` builds | `eas credentials` (development) or local `~/.android/debug.keystore` |
| **Upload key** | The `.aab` EAS signs and uploads to Play | `eas credentials` (production profile) |
| **Play App Signing key** | The build Google **re-signs** and serves to real users from the Play Store | Play Console → App signing page |

The critical insight: the app a user downloads from the Play Store is signed by
**Google's App Signing key**, NOT your upload key. So even if Google Sign-In
works in a debug build or a sideloaded APK, it will fail on the Play Store build
unless the **Play App Signing SHA-1** is registered.

`google-services.json` currently has a single Android fingerprint
(`certificate_hash`), which is only the test/upload key. The Play App Signing
fingerprint is almost certainly the missing one.

## Step 1 — Confirm you are on Play App Signing

1. Run the EAS credentials viewer for Android:
   ```bash
   npx eas-cli credentials -p android
   ```
   Choose the **production** profile. EAS prints the keystore it manages plus its
   **SHA-1** and **SHA-256** fingerprints. This is your **upload key**.
2. Open **Google Play Console** → your app → **Release → Setup → App signing**.
   - If this page exists, you are using **Play App Signing** (the default for new
     apps), which is why a separate production SHA-1 is required.
   - You will see two certificates:
     - **App signing key certificate** → Google's key. Its SHA-1 is the one most
       likely missing from Firebase.
     - **Upload key certificate** → matches the EAS upload key from step 1.

---

## Step 2 — Collect every SHA-1 you need

Gather the SHA-1 (and SHA-256, which Firebase also accepts) for each key you
actually ship:

- **Debug / development build:**
  ```bash
  npx eas-cli credentials -p android   # development profile
  ```
  Or, for the local Android debug keystore:
  ```bash
  keytool -list -v \
    -keystore ~/.android/debug.keystore \
    -alias androiddebugkey \
    -storepass android -keypass android
  ```
- **Upload key:** from the `eas credentials` production output (step 1).
- **Play App Signing key:** copy the SHA-1 (and SHA-256) directly from the Play
  Console **App signing** page.

Keep them in colon-separated form, e.g. `AB:CD:12:...:EF`.

---

## Step 3 — Register the fingerprints in Firebase

`google-services.json` is generated by Firebase, so add fingerprints there (not
by hand-editing the JSON):

1. Open the [Firebase Console](https://console.firebase.google.com/project/dressfair-react-native/settings/general)
   for project **`dressfair-react-native`**.
2. **Project settings → Your apps →** the Android app
   (`com.dressfair.dressfairrnhybrid`).
3. Click **Add fingerprint** and paste each SHA-1 you don't already have
   (do the SHA-256 versions too). At minimum add the **Play App Signing** SHA-1.
4. Save.

> Firebase stores each fingerprint as a lowercase, colon-free `certificate_hash`
> inside `google-services.json`. The existing value
> `5e8f16062ea3cd2c4a0d547876baa6f38cabf625` is just one such hash.

---

## Step 4 — Refresh `google-services.json`

1. Still in Firebase → Project settings → Your apps → Android app → **Download
   google-services.json**.
2. Replace the file at the repo root (`./google-services.json`). `app.json`
   already references it via `android.googleServicesFile`.
3. Confirm the new file now has **multiple** `oauth_client` entries with
   `client_type: 1` — one per registered fingerprint.
4. Commit it. Per [`FIREBASE_SETUP.md`](../FIREBASE_SETUP.md) these config files
   contain no private secrets and are kept in git so EAS Build picks them up.

---

## Step 5 — Rebuild, resubmit, and verify

1. Produce and submit a production build:
   ```bash
   eas build --platform android --profile production
   eas submit --platform android --profile production   # or push to the existing internal track
   ```
2. Install the build **from Play** (use the internal testing link) on a real
   device — **not** a sideloaded APK. Only the Play-served build carries the App
   Signing key, so only it exercises the production SHA-1.
3. Tap **Continue with Google** and confirm sign-in succeeds. In analytics you
   should see `auth_google_login { ok: true }` and **no** `DEVELOPER_ERROR` /
   status-10 failure.

---

## iOS and Apple — no SHA needed

- **iOS Google Sign-In** uses the bundle ID + reversed iOS client ID
  (`googleIosClientId` in `app.json` + `GoogleService-Info.plist`). The
  google-signin config plugin wires the URL scheme during prebuild. No SHA-1.
- **Apple Sign-In** is native on iOS only (`expo-apple-authentication`) and uses
  no SHA-1. The Android Apple button is intentionally hidden in
  [`LoginChooserScreen.tsx`](../src/features/auth/screens/LoginChooserScreen.tsx)
  until an Apple Services ID + HTTPS return URL relay exists
  (`appleServicesId` / `appleRedirectUri` are empty today).

## Troubleshooting

| Symptom | Fix |
| --- | --- |
| Google Sign-In works in debug but fails on Play Store build | Register the **Play App Signing** SHA-1 (Step 1–3), re-download `google-services.json`. |
| `DEVELOPER_ERROR` / status code 10 | A fingerprint for the current build's signing key is missing in Firebase, or `google-services.json` is stale. |
| Works on sideloaded APK but not Play install | Sideloaded APK uses the upload key; Play install uses Google's App Signing key — add that SHA-1. |
| Changed package name or new keystore | Re-collect SHA-1s and repeat Steps 2–5. |
